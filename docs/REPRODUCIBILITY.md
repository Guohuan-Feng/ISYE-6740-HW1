# Reproducibility

Run [HW1_completed.ipynb](../HW1_completed.ipynb) from the repository root with the supplied datasets in `data/`. The notebook contains the code, derivations, saved tables, and figures for all six exercises. No account credentials or external dataset downloads are required to execute it.

## Environment

The recorded run used **Python 3.12.14**. Use Python 3.12 and install the pinned dependencies in [requirements.txt](../requirements.txt).

| Dependency | Recorded version | Role |
| --- | --- | --- |
| NumPy | 2.3.5 | Arrays, linear algebra, and simulation |
| pandas | 3.0.1 | Data loading and result tables |
| SciPy | 1.18.1 | Optimization support and normal CDF |
| scikit-learn | 1.9.1 | Regression, classification, and scaling |
| Matplotlib | 3.11.2 | Figures |
| xlrd | 2.0.2 | Reading the supplied legacy `.xls` files |
| threadpoolctl | 3.7.0 | Numerical thread limits |
| nbformat | 5.11.1 | Notebook validation |
| nbclient | 0.11.0 | Fresh-kernel notebook execution |
| nbconvert | 7.17.1 | Notebook conversion |
| ipykernel | 7.3.0 | Python notebook kernel |

Package installation requires access to a Python package index unless the dependencies are already available locally. The analysis itself reads local files.

From the repository root on Windows PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install --upgrade pip
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe scripts/verify.py
.\.venv\Scripts\python.exe scripts/verify.py --execute
```

On macOS or Linux:

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python scripts/verify.py
python scripts/verify.py --execute
```

Using the virtual environment's Python explicitly avoids accidentally mixing notebook packages from different installations.

## Verification modes

`python scripts/verify.py` performs the repository's static checks without rerunning the experiments. Use it to check the saved deliverable and required local inputs. Passing static checks alone does not establish that the notebook executes successfully in a newly installed environment.

`python scripts/verify.py --execute` performs a fresh notebook execution and writes generated artifacts under `build/`. Use this mode when validating a new environment or a code change. The repository root is the execution working directory so that `data/` resolves consistently. Review the command's reported output paths and any failure before using the generated notebook.

The root notebook is the versioned deliverable; `build/` holds regenerated outputs. Execution should proceed from the setup cell through Q6 in order. Running isolated later cells may fail because they depend on imports, fitted models, or arrays from earlier cells.

A successful fresh run produces `build/HW1_completed.ipynb`, `build/HW1_completed.html`, and `build/validation.json`. The verification workflow uploads this directory as the `hw1-verification` artifact, including diagnostic outputs if a run fails.

To refresh the published reading copies after intentionally updating the root notebook's saved outputs, run `python scripts/export_assets.py`. This extracts the nine gallery PNGs, rebuilds `HW1_completed.html`, and creates `docs/index.html` with report navigation. GitHub Pages serves `docs/` from `main`; `docs/.nojekyll` keeps the exported HTML unchanged.

For interactive work, open the notebook in an editor that supports Jupyter notebooks and select this virtual environment's Python kernel. A JupyterLab interface is optional and is not included in the analysis requirements; install it separately if desired. Restart the kernel and run all cells when verifying a complete result.

## Deterministic choices

The notebook preserves the supplied train/test splits and does not reshuffle rows. Q5 uses n ∈ {100, 200, 500, 1,000, 2,000, 5,000, 10,000, 20,000} in their original order. Q6 uses `numpy.random.default_rng(6740)`, first drawing disease statuses and then test results.

Scalers are fitted only on training features and reused for the corresponding test features. The setup limits supported BLAS/OpenMP thread pools to one thread. Solvers and their tolerances are set in the relevant exercise cells.

Key settings to preserve are:

| Exercise | Setting |
| --- | --- |
| Q1 initial raw GD | Stepsize 6 × 10⁻⁷; maximum 100,000 updates; stop at update norm below 10⁻⁵ |
| Q1 stability and standardized comparisons | Hessian-based stepsizes; gradient norm below 10⁻⁵; intercept included |
| Q1 momentum | Same standardized stepsize as GD; β = 0.9; zero current and previous iterates |
| Q2 LAD | Quantile 0.5; α = 1; original feature units |
| Q2 Huber | Training-standardized features; α = 0; ε ∈ {1.1, 1.35, 2, 5} |
| Q3 logistic regression | Original units; C = 1; Newton–Cholesky; tolerance 10⁻⁹ |
| Q4 KNN | Requested odd K grids; both Euclidean and Manhattan distance |
| Q5 logistic regression | C = 1; L-BFGS; tolerance 10⁻⁴; at most 10,000 iterations |
| Q6 simulation | Seed 6740; population size 1,000,000; prevalence 0.001 |

## What should match

Use [RESULTS.md](RESULTS.md) as the numerical reference. Useful landmarks include Q1 OLS test MSE **130.571625**; Q2 LAD test MSE **137.739939**; Q3 logistic regression **137 misclassifications**; Q4 logistic error **0.220472**; and Q5 population Bayes error **0.1586552539**.

With the recorded environment and unchanged random-number draw sequence, Q6 yields **958 true positives, 9 false negatives, 9,938 false positives, and 989,095 true negatives**. A different seed or random-number call order changes the simulated counts.

Do not require byte-for-byte identical notebooks or HTML. Execution metadata, table identifiers, floating-point rounding, and rendering can differ. BLAS libraries and optimizer behavior may also affect final digits or iteration counts near a tolerance boundary. Investigate meaningful changes in predictions, convergence status, or the qualitative conclusions.

The raw Q1 GD stopping result is particularly easy to misread: its update tolerance is reached after 6,098 iterations even though its gradient norm remains about 16.66. This is the prescribed stopping criterion, not evidence that the OLS coefficients have been recovered. The raw run using a gradient-norm criterion at half its stability bound instead reaches the 100,000-iteration limit.

Finally, reproducibility does not remove statistical limitations. The requested test-set sweeps are descriptive comparisons. Model or hyperparameter selection for a new predictive application should use validation data or cross-validation and reserve an untouched test set for the final evaluation.
